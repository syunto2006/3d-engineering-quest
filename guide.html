CADの経験を足場に、プログラムを書く力を育てます。1課題は目安10〜20分。64課題で複数日に分けて進める開発キットです。

このキットの進め方

解説›コードを書く›実行・テスト›理解チェック›次の鍵
  1. 学習マップから開放されている章へ入る。
  2. 左の解説と課題を読み、右のコードを編集する。ファイル名を切り替えると、ほかのファイルも読めます。
  3. 「実行してテスト」で結果を確認。Ctrl+Enterでも実行できます。
  4. 詰まったらヒントを一段ずつ開く。「今のエラーを読み解く」はエラーの種類に応じた固定の説明です。AIや外部APIは使いません。
  5. コードのテストと理解チェックに合格すると、今回のコードが自分のプロジェクトへ入り、次へ進めます。

app.jsは機能をつなぐ補助コードとして最初から入っています。64課題では、その中から呼び出す各機能を自作します。すべてのソースを読めて、最後にZIPとして持ち出せます。ゼロから自力で再現するには、各章の後で解答例を閉じて書き直し、入力を変えて結果を説明してみてください。

メモ、入力途中のコード、進捗は自動保存。端末を移る前はホーム画面から学習記録を保存します。完成見本を触っても、自分の進捗は変わりません。

アプリの設計図

index.html  画面の骨格
style.css   色・大きさ・配置
app.js      下の機能をつなぐ補助コード
├ state.js    部品や選択状態
├ world.js    カメラ・描画・光
├ parts.js    STLと座標変換
├ ui.js       一覧・透明化・部品選択
├ sequence.js 組立順と位置の計算
└ storage.js  JSON保存・読み込み
requirements.json  目的・要件・受入条件

まず「誰の、何の問題か」を考える要求分析。それを確認できる条件にする要件定義。処理の順と分岐を描くフローチャート。機能ごとに担当を分けるファイル構成。この順で考えてからコードへ進みます。

STL選択›形式・容量の検証›成功：部品表示／失敗：理由表示

実際のアプリでは、利用者の操作→状態の変更→画面の更新を繰り返します。

線形代数の入り口

位置p=[x,y,z]をd=[dx,dy,dz]だけ動かすなら、p'=p+d。倍率をs倍にするならp'=sp。回転を含む複数の変換は、4×4の行列にまとめて計算できます。Three.jsのposition・rotation・scaleが、その計算を扱いやすくしてくれます。

開始aから到着bへ向かう位置はp(t)=a+(b−a)t（0≤t≤1）。組立アニメーションでは時間tを少しずつ進めます。動画編集のキーフレームや、CSSのアニメーションにも「間の値を計算する」という同じ考え方があります。

自分のアプリをGitHubで公開

  1. 制作室で「全ソースをZIPで保存」。解凍する。
  2. GitHubで自分の作品用リポジトリを作る。Publicを選ぶとコードも公開されます。
  3. Add file → Upload filesで、解凍したフォルダの中身をアップロード。index.htmlがルートに来るようにする。
  4. Commit changesで「組立ビューアを追加」と説明して保存。
  5. Settings → Pages → Deploy from a branch → main / (root) → Save。
  6. Actionsで配信完了を確認し、Pagesに表示されたURLを開く。

この学習サイトのファイルと自分の作品を混ぜないため、新しいリポジトリを使うと分かりやすくなります。ローカルで試すなら、Pythonがある環境で解凍先から python -m http.server 8000 を実行し、http://localhost:8000 を開きます。HTMLのダブルクリックではSTL読み込みが制限される場合があります。

ブランチは試すための枝、コミットは保存記録、PRは差分を確認して取り込む相談です。練習ではREADMEを変更するpractice/readmeブランチを作り、PRのFiles changedを読んでmainへマージしてみましょう。コミットしても、配信設定がなければサイトは公開されません。
